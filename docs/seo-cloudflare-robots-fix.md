# Cloudflare Managed robots.txt — disable in dashboard

## Problem

The deployed site at `https://theuaecareer.com/robots.txt` is NOT serving the
robots.txt generated by `app/robots.ts`. Instead, Cloudflare is serving its
own "Managed robots.txt" with a `Content-Signal` header.

You can verify this by comparing:

```bash
curl -s https://theuaecareer.com/robots.txt
```

You should see a Cloudflare-managed file starting with:

```
# As a condition of accessing this website, you agree to abide by the following
# content signals:
...
User-agent: *
Content-Signal: search=yes,ai-train=no
Allow: /
```

instead of the project's own robots.txt which includes:

```
User-Agent: *
Allow: /
Disallow: /admin/
Disallow: /api/
Disallow: /studio/
Disallow: /cdn-cgi/
...
Sitemap: https://theuaecareer.com/sitemap.xml
```

## Impact

1. **No `Sitemap:` directive** in the served robots.txt — Google cannot
   auto-discover `sitemap.xml` from robots.txt. The sitemap is still indexable
   if submitted manually in Google Search Console, but auto-discovery is broken.
2. **Site `Disallow` rules are bypassed** — `/admin/`, `/api/`, `/studio/`,
   `/cdn-cgi/` are no longer disallowed, exposing them to crawlers (low risk
   here because those routes 404 or are blocked elsewhere, but still wrong).
3. **AI training rules are bypassed** — GPTBot, CCBot, Bytespider are no
   longer blocked from training crawls.
4. **Non-standard `Content-Signal` header** is served, which some crawlers
   may handle inconsistently.

## How to fix

You must disable Cloudflare's Managed robots.txt feature in the dashboard. It
is not something this codebase can control.

1. Open https://dash.cloudflare.com
2. Select the `theuaecareer.com` zone
3. Go to **Bots** → **Settings** (or **Security** → **Bots** depending on
   dashboard version)
4. Find **Managed robots.txt** (also labeled "AI content-signal robots.txt")
5. Toggle it **OFF**
6. Wait ~5 minutes for edge cache to clear, then re-test:

   ```bash
   curl -s https://theuaecareer.com/robots.txt | head -20
   ```

   You should now see the project's own robots.txt with `Disallow` rules and
   the `Sitemap:` line.

## After fixing

In Google Search Console, also do the following to accelerate recrawl:

1. **Settings → Crawling → robots.txt** — click **Request a recrawl**
2. **Sitemaps** — re-submit `https://theuaecareer.com/sitemap.xml`
3. **URL Inspection** — inspect the homepage and click "Request Indexing"

## Why this is suspected as part of the impressions drop

This Cloudflare feature was likely enabled around the same time the project
moved to Cloudflare Pages. The Search Console impressions cliff on 2026-04-24
correlates with the "SEO deep cleanup" merge being deployed, but the underlying
sitemap-discovery issue from this override would have compounded any ranking
volatility from new content.
